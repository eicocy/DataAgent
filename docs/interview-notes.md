# 设计取舍

**计划为何受限？** Pydantic 校验工具和参数，执行来自固定 Pandas/SQL 实现；模型无法指定用户、路径、连接或任意代码。

**为何完整结果与摘要分离？** 筛选后聚合必须使用全部筛选结果。source_ref 连接完整工件，模型和页面只获取预算内摘要/预览，裁剪不改变数值。

**为何单 Agent？** 难点是衔接、预算、失败恢复及证据，显式计划与确定性执行更容易维护和测试，不需要角色对话。

**为何 SQL 多层限制？** AST 约束语句和字段，数据库权限阻止写入与业务表访问，LIMIT 不限制扫描成本，所以还需期限与结果预算。

**为何 MySQL 任务？** 复用单机现有数据库，保存幂等 ID、状态和 Trace，避免额外运维；限制是单实例，不能直接横向扩容。

**如何测试模型？** Mock 测试断言合法计划、引用、数值、权限、预算和状态，不比较自由文本全文。独立 MySQL 测试验证迁移/类型/权限，付费真实模型留给显式验收。

**成功如何判定？** 必需步骤和报告完成才 succeeded，已有计算但后续失败 partial，没有结果 failed。Trace 是执行证据，不是隐藏思维链。

展示时区分已交付代码、自动化验证和外部服务验收。Docker/MySQL/DeepSeek 未执行前不声称完成生产认证或高可用。
