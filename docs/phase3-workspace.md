# Workspace Phase 3 — 数据分析工具与可确认的数据变更

本阶段基于 V2.0.2，交付 V2.0.3。范围来自 `UPGRADE_PLAN.md` 的新版 Phase 3；旧版 v2.0.0 的 Phase 4 编号属于历史记录。本次没有实施新版 Phase 4/5。

## 文件、版本与发布

统一文件入口支持原有 CSV/TSV、JSON/JSONL、Excel、Parquet 表格，以及 TXT/PDF/DOCX 文档。文档提取提供有限原文和候选表样例、原文位置、可能表头；用户必须核对并明确确认，才创建可分析的数据集。无候选表的文档保留文档状态，不假造数值表；没有 OCR、旧 DOC 或加密 PDF 支持。附件“收起预览”仅关闭当前预览，刷新可恢复会话附件。

`0011_workspace_files` 新增 UploadedFile 和可空的数据集来源字段，保留旧 Dataset/Version/Session/分析记录。表格解析、文档提取和变更发布沿用持久队列及独立受监督进程；接受请求不等于任务成功，界面继续查询终态。排队/运行分析的所有固定输入均受删除忙碌保护；提交与删除共用用户行互斥和当前读取，删除先检查活动 Job/右输入发布记录，再锁 Dataset，避免与发布器形成相反锁顺序。提交只按序锁定实际请求/当前目标版本，不加载全部历史版本。

质量评分 `quality-score-v1` 使用公开缺失、空值、重复、无效类型、非有限值和明确范围违规扣分规则。它是描述性启发式，不能当行业标准。空表无分数；完整问题计数与有限行号样例分别展示。系统不自动改变数据口径。

清洗允许 1–8 项显式操作：重命名、去重、删除缺失、填补缺失、类型转换、日期解析、替换值、文本规范和异常值处理。先固定源版本预览前后计数、质量与步骤日志，再确认保存。幂等键和预览 hash 绑定完整参数；过期源版本 CAS 返回冲突。结果写入新投影/新 DatasetVersion，旧版本和原文件保留。

Join 选择拥有的右表及固定版本、逐对排列左右键、inner/left 和 one_to_one/many_to_one/one_to_many。拒绝多对多、空键、类型不匹配与超预算展开；完整计数、未匹配数和两侧版本来源可核对。发布仍创建左表新版本，来源必须包含两张表，不能声称仅左表原文件即可重现。

## 业务计算和预测

`kpi_analysis`、`period_comparison`、`contribution_analysis` 通过 Registry 类型化输入/结果执行。收入/GMV/成本/利润/费用/预算/实际等概念保持区分；金额币种与单位必须显式确认或由一致的可信元数据列验证。数量比较需要单位，纯计数不强制币种；不自动换汇或混合单位。

受支持 Decimal 输入的合计与差值返回精确十进制文本；比例保留 28 位有效数字。授权固定版本加载可 opt-in 保留已存储 Decimal，结构性清洗和 Join 保留精度。首次 CSV 数值解析和旧投影仍可能经过浮点/八位小数近似，无法恢复已经丢失的精度；统计填补等操作也不能宣称精确财务结算。

比较区间采用 `[start,end)`，按日/月/季/年明确边界、覆盖和比较口径。零分母、覆盖不足返回原因。贡献列出完整分类并验证分组差值之和等于总差值；这说明数值贡献，不证明因果。“今年”按 Asia/Shanghai 当前年份解释，历史样本问题应写明历史区间。

预测至少 12 个连续规则周期，且满足三折 horizon 的历史长度。Naive、三期均值、线性趋势、非季节 ETS 和有界 ARIMA 使用相同三个扩展时间窗口；MAE 主比较、RMSE 辅助，保留 Naive 基线、模型失败和 MAPE 非零目标覆盖。最终拟合在验证之后执行，不填补缺失周期，不默认推断季节性。误差上下界来自验证绝对残差的经验分位数，未经校准，不能称为可信的 90% 预测区间。

## Agent 与界面边界

Profile 是 Planner 策略，不是固定领域 Workflow。通用质量、销售、财务、预测四类对应实际工具，其余目录项仍按可用/通用/规划状态展示。Agent 使用授权固定输入、语义快照、受限 DAG、期限和调用预算；Join 衍生字段继续接受币种/单位校验。并行只读节点的存活工作线程保留预算预留，超时不能释放仍在运行的资源。

界面使用真实候选确认、质量、清洗和 Join API；版本切换期间不展示另一版本样例。完整 typed 结果显示实际指标、误差和验证说明。只有 normalized table 时保留实际行和值，并明确完整计算信息未提供，不补造指标、评分或预测点。部分读取路径的报告表适配仍不保留完整 typed 元数据；统一 Artifact/Chart/Report 协议属于 Phase 4。

自动多格式交付、Artifact 引用/长期留存、报告系统升级、Python 沙箱仍未实施。当前手动报告/导出沿用原系统，不能作为上述新阶段已完成的证据。

## 验收证据边界

本阶段验收均使用明确标记的模拟数据和独立测试账号。守护全套测试使用临时 SQLite、独立文件目录、空模型 Key；真实 MySQL 使用仅本次创建的三个精确名单测试库。真实 API 验证了文档候选确认、七个监督任务终态、清洗/Join、并发幂等、CAS 和旧版本不变；已存储 Decimal 的真实 MySQL 验证不扩大为首次 CSV 解析精度承诺。

真实模型一次完成四项工具：overview、周期、贡献和预测。历史模型失败、30 秒阶段超时及成功样本中的旧 MAPE 文本格式错误分别保留；修正后的确定性事实重渲染使用同一批真实工件，没有追加模型调用，也没有修改历史存储答案。完整数字、运行限制与最终测试收据见 [V2.0.3 发行说明](releases/v2.0.3.md)。
