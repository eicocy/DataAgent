# Phase 5 实施计划

基线：V2.0.4 / `8ab210d`。按 `UPGRADE_PLAN.md` Phase 5 继续，用户已授权完成后提交、推送并发行 V2.0.5。

## 范围与任务

1. 定义默认关闭的 SandboxSettings、严格 AST 和固定输入/输出协议；仅接收已授权、固定版本的快照，输出校验 JSON、完整表格与 PNG。
2. 实现独立 Docker broker 与执行镜像。应用不访问 Docker；执行容器非 root、只读、无网络、无 capability、禁止提权，固定 1 CPU / 512 MiB / 64 PID / 60 秒 / 64 MiB 输出。租约过期、取消和重启清理工件容器；不可用时明确失败。
3. 现有工具优先。仅注册工具无法满足且返回未知能力时生成受限代码提案；拒绝公开代码入口。复用现有 Agent 任务、预算、固定输入、结果校验、Evidence、Artifact 和报告交付，保持普通分析不依赖沙箱。
4. 加固任务取消/孤儿清理、安全日志及 Nginx SSE；提供可选 Compose 沙箱配置和备份/恢复/运行手册。数据库迁移头保持 0012，不新增默认表。
5. 集中验收、更新能力与索引、V2.0.5 发行。保留用户本地配置和 plan/，不得把凭据及运行数据提交。

## 检查策略

开发中仅运行本次改动对应的 AST/协议、broker 生命周期、授权/预算/取消与恢复检查，模型使用固定样例。低风险文档/文案仅静态或构建检查。Docker 攻击验证是本次隔离契约检查，不扩展为压力或兼容性测试。已有强制 CI 保持。

最终集中做一份小模拟数据的真实链路：分析结果、Artifact、预览与下载，PDF/DOCX/XLSX 各生成并检查一个文件；真实 Docker 验证资源、超时、取消、输出攻击及孤儿清理。隔离 MySQL 从 0009 升级、旧数据与备份恢复；真实模型仅最终关键链路调用一次，环境不可用应记录未验证。一次独立整分支审查，失败不虚报。

## 接口约束与决定

- Validator 同时由应用与 broker 执行，runner 再次执行；AST 属于纵深校验，Docker 是执行隔离边界。
- broker 只接受固定 JSON 协议，不接受镜像、路径、Docker 参数或挂载；输入通过容器标准输入传入内存，无宿主目录挂载。
- 输出经受限 tar 读取与严格类型校验；只接受固定结果 JSON 与 PNG，PNG 解码后重新编码。表格以 JSON 行表示，避免 CSV 类型/公式歧义。
- 默认关闭。应用只声明配置状态；broker 健康确认后才提出沙箱代码，不以配置为可用证明。
- 不执行生产部署或业务库迁移；隔离验收及操作手册不代表生产环境已部署。

前置接口检查：任务 1 的协议供任务 2/3 共用；任务 2 的 heartbeat/cancel-owner 供任务 3/4 处理租约；任务 3 的表格结果与既有 Artifact/报告共用当前版本。无新增公开代码路由，无默认数据库变更。
