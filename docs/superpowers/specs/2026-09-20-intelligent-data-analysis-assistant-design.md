# 接入大模型 Agent 的智能数据分析助手：开发前设计规格

## 1. 文档目的

本规格定义“接入大模型 Agent 的智能数据分析助手”的开发前设计交付物。项目当前阶段仅进行产品、交互、前端、后端、数据库、接口、Agent 与 Tool 体系设计，并制作可在浏览器直接查看的静态 HTML 产品原型。

本阶段不创建 Vue、FastAPI 或数据库运行工程，不安装依赖，不接入 DeepSeek API，不实现真实文件解析、数据计算、身份认证或接口请求。

## 2. 项目目标

面向不会 Python、SQL 或复杂 Excel 操作的用户，设计一套可以通过自然语言完成常见数据分析任务的产品方案。用户上传 Excel 或 CSV 后，可以提出数据查询、筛选、聚合、趋势分析、指标计算、SQL 查询、图表生成和数据总结等问题。

系统设计必须坚持“模型理解与规划，Tool 真实计算”：

- 大模型负责理解意图、选择 Tool、生成结构化参数和总结计算结果。
- Pandas 或受控 SQL Tool 负责读取和计算真实数据。
- 大模型不得直接猜测数据结果。
- Agent 不得生成并执行任意 Python 代码。
- SQL Tool 只允许执行受约束的只读查询。

## 3. 目标用户与使用场景

主要用户包括数据分析初学者、学生、运营人员、销售人员和小型企业工作人员。

核心场景包括：

1. 上传销售数据并统计不同地区销售额。
2. 分析最近 12 个月的销售趋势。
3. 筛选销售额超过指定金额的记录。
4. 将聚合结果生成柱状图、折线图或饼图。
5. 使用自然语言发起安全、只读的数据查询。
6. 查看 Agent 的意图判断、Tool 参数、计算结果和最终总结。
7. 保存、查看和再次执行历史分析。

## 4. 总体设计原则

设计优先级为：清晰性、可实现性、工程规范、技术复杂度。

- 采用单体前后端分离架构，不采用微服务。
- 技术范围限定为 Vue 3、Vite、Vue Router、Pinia、Axios、Element Plus、ECharts、FastAPI、LangChain、DeepSeek API、Pandas、SQLAlchemy 和 MySQL。
- 不引入 Kafka、Redis、Kubernetes、LangGraph 或复杂工作流平台。
- 模块边界需要便于本科生独立实现和面试讲解。
- 所有页面必须覆盖正常、加载、空数据、成功、失败和无权限状态。
- 原型展示的数据均为模拟数据，并在页面中明确标识。

## 5. 交付范围

### 5.1 根目录总览

根目录提供项目说明、总体架构、核心流程、数据流、目录设计和开发阶段建议，负责串联各设计板块。

### 5.2 产品原型

产品原型包含 Markdown 设计说明和多页面静态 HTML 高保真原型，覆盖：

- 用户系统：登录、注册、个人信息。
- Dashboard：数据概览、最近数据集、最近分析、快速入口。
- 数据集管理：列表、上传、详情、数据预览、字段信息。
- Agent 智能分析：分析工作台、对话、执行过程、Tool 调用、分析结果和推荐问题。
- 图表分析：图表展示、图表配置、图表与数据表联动。
- 分析会话：会话列表、切换、删除和恢复提示。
- 分析历史：历史列表、分析详情、再次分析。
- 通用反馈：空状态、加载状态、错误状态、权限异常和文件解析失败。

### 5.3 前端设计

前端设计包括 Vue 3 工程结构、路由、Pinia 状态划分、Axios 请求层、数据模型、核心组件、分析工作台组件、ECharts 接入边界、交互状态和 HTML 原型迁移说明。

### 5.4 后端设计

后端设计包括 FastAPI 分层目录、模块职责、数据访问边界、Agent 编排、Tool 注册与执行、文件上传与解析、只读 SQL 安全、认证和数据权限、异常处理与日志。

### 5.5 数据库设计

数据库设计至少包含 users、datasets、dataset_columns、analysis_sessions、analysis_messages 和 analysis_records，并说明字段、类型、主外键、索引、约束、表关系、数据生命周期和初始化顺序。

### 5.6 项目接口

接口统一使用 `/api/v1` 前缀，覆盖认证、数据集、智能分析、分析会话和历史记录；定义统一响应、分页、错误码、Agent 与 Tool 数据协议以及图表数据协议。

重点接口 `POST /analysis/chat` 的设计响应至少包含：

- `session_id`
- `message_id`
- `answer`
- `tool_name`
- `tool_parameters`
- `tool_result`
- `chart`
- `execution_time`

## 7. HTML 原型设计

### 7.1 原型形态

采用多页面静态 HTML 原型，并提供统一的 `产品原型/index.html` 原型入口。所有页面使用原生 HTML、CSS 和少量 JavaScript，实现页面跳转和必要的演示交互，不依赖 npm 或网络资源。

### 7.2 视觉方向

- 现代、专业、简洁的浅色 SaaS 数据分析后台。
- 以清爽蓝色作为主强调色，深蓝灰用于导航和文字层级。
- 主要设计宽度为 1440px，并为较窄桌面窗口提供基本适配。
- 避免无意义的渐变、复杂动画和装饰性图表。
- 使用清晰的字号、留白、卡片、表格和状态色建立信息层级。

### 7.3 全局页面框架

登录与注册页面采用独立品牌布局。登录后的页面采用统一侧边栏、顶部栏和主内容区：

- 侧边栏：Dashboard、数据集、智能分析、分析会话、分析历史。
- 顶部栏：页面标题、当前位置、通知占位和用户入口。
- 主内容区：根据页面职责呈现概览卡片、表格、表单、工作台或详情。

### 7.4 分析工作台

分析工作台是原型重点，采用三栏结构：

- 左栏：当前数据集、字段列表、字段类型、缺失值提示和推荐问题。
- 中栏：用户与 AI 消息、问题输入、Agent 状态和执行时间线。
- 右栏：指标、数据表、图表、Tool 结果和 AI 最终总结。

页面需要清楚展示以下链路：

```text
用户问题
→ Agent 理解意图
→ 选择 Tool
→ 生成结构化参数
→ Tool 执行真实计算
→ 返回计算结果
→ 生成图表
→ AI 总结
→ 保存分析记录
```

Tool 调用卡片必须显示 Tool 名称、参数、执行状态、耗时和结果摘要。它是产品区别于普通聊天机器人的核心视觉证据。

### 7.5 原型交互边界

原型可演示：

- 页面和侧边栏跳转。
- Tab、折叠区、下拉区和模态框。
- 上传中、解析中、成功和失败等状态切换。
- Agent 执行步骤展开与收起。
- 表格与图表视图切换。
- 删除确认和错误反馈。

原型不执行：

- 真实登录或注册。
- 真实文件上传、解析和保存。
- 真实接口请求。
- 真实 Agent、Tool、Pandas 或 SQL 计算。
- 真实数据库读写。

## 8. 页面原型文档要求

每个页面对应的设计文档必须说明：

1. 页面目标和适用角色。
2. 用户进入路径和离开路径。
3. 页面结构和信息层级。
4. 主要控件、按钮、表格和卡片。
5. 用户操作及系统反馈。
6. 加载、空数据、成功、失败和无权限状态。
7. 示例数据和展示文案。
8. 对应的前端组件。
9. 调用的 API。
10. 与其他页面的跳转关系。
11. 响应式处理建议。
12. 开发验收要点。

## 9. Agent 与 Tool 设计约束

Agent 流程为：读取数据集 Schema，将问题和 Schema 交给模型，模型选择 Tool 并生成结构化参数，Tool 进行真实计算，模型仅基于 Tool Result 总结，结果和执行证据写入分析记录。

首期 Tool 包括：

- `get_dataset_info`
- `preview_data`
- `filter_data`
- `aggregate_data`
- `group_by_analysis`
- `sort_data`
- `sql_query`
- `generate_chart`

每个 Tool 文档需要包含名称、描述、适用场景、结构化输入、输出结构、校验规则、错误类型和示例调用。Tool 不接受自由 Python 代码。

## 10. SQL 安全约束

`sql_query` 仅允许单条 `SELECT` 查询，并执行以下限制：

- 禁止 INSERT、UPDATE、DELETE、DROP、ALTER、TRUNCATE 和 CREATE。
- 只允许访问当前用户被授权的数据集映射表或只读视图。
- 校验表白名单和字段范围。
- 拒绝多语句、注释绕过和危险函数。
- 强制结果行数上限和查询超时。
- 数据库连接使用只读账号。
- 对外返回可理解的安全错误，不泄露连接信息和内部堆栈。

## 11. 数据流

核心数据流如下：

```text
Vue 页面
→ POST /api/v1/analysis/chat
→ FastAPI Analysis Controller
→ Analysis Service
→ Agent Executor
→ 结构化 Tool
→ Pandas 或受控只读 SQL
→ Tool Result
→ LLM Summary
→ Analysis Record
→ API Response
→ Vue 状态层
→ 表格、图表和总结区域
```

正式设计文档需使用 Mermaid 补充系统架构图、ER 图、数据流图和关键接口时序图。

## 12. 文档一致性要求

- 页面名称、路由名称、API 名称、数据库实体名称和 Tool 名称必须跨文档一致。
- 页面与 API、数据库表和前端组件之间需要提供映射表。
- 示例数据使用统一的销售数据集语境，避免同一流程出现互相矛盾的字段。
- 统一示例字段建议使用 `order_date`、`region`、`product`、`sales` 和 `quantity`。
- 文档不得声称原型具备真实运行、计算或持久化能力。

## 13. 验收标准

设计交付完成时应满足：

1. PRD、信息架构、页面原型、交互设计、前端、后端、数据库、API、Agent、Tool、SQL 安全、项目目录和数据流均有独立且可关联的文档。
2. 所有用户可见功能模块均有可浏览的 HTML 页面原型。
3. `产品原型/index.html` 可以作为原型导航入口。
4. 页面之间具备足够的点击跳转和状态演示能力。
5. 分析工作台完整呈现 Agent 与 Tool 的执行证据链。
6. 每个核心页面覆盖加载、空、成功和失败状态。
7. HTML 原型不依赖后端、数据库、npm 或外部 CDN。
8. 原型、接口、数据库和架构文档中的术语与字段保持一致。
9. 设计复杂度适合本科生在单体项目中实现和讲解。

## 14. 明确排除项

本阶段不包含：

- Vue 3、FastAPI、LangChain 或 MySQL 的可运行项目。
- 依赖安装、环境配置、启动命令和部署脚本。
- 真实业务代码、自动化测试和运行结果。
- DeepSeek API 调用与密钥配置。
- Excel 或 CSV 的真实上传、解析与分析。
- 真实图表计算、SQL 执行或数据库初始化脚本。
- 微服务、消息队列、缓存集群、容器编排和复杂工作流引擎。
