# Phase 4：Artifact / Chart / Report 工作区

2026-10-05，仅实施 `UPGRADE_PLAN.md` 的 Phase 4。代码在 `codex/phase4-artifact-report`，仍沿用 V2.0.3 包版本，未提交、发行、部署或进入 Phase 5。`phase4-implementation.md` 属于 v2.0.0 历史记录，与本文件分开。

## 已交付的行为

- ArtifactManager 统一 JSON 计算结果和二进制导出文件的授权、状态、公开 DTO、会话归属、配额和留存。最终成果及所需证据没有自动过期时间；未引用中间成果沿用七天。默认每用户 2 GiB，可通过进程环境变量 `ARTIFACT_USER_MAX_BYTES` 调整。容量不足拒绝写入，不自动删除最终成果；可通过现有会话/数据集删除流程清理。
- `GET/PATCH /analysis/sessions/{id}/workspace` 恢复分页成果、报告列表、最新分析及选中成果。选中成果超出第一页时仍返回其 DTO。手动报告不会遮蔽最近分析；客户端按顺序保存连续选择，隔离旧会话的迟到响应。
- `GET /artifacts` 支持 `session_id/type/status` 过滤。缺失文件和已清理文件显示 EXPIRED。预览最多返回有界行数，下载 JSON 使用完整保存内容；报告、表格、图表和代码共用授权下载入口。
- `artifact_refs` 发送结构化 ID；服务端核对用户、会话、类型、固定输入版本和完整文件。图表引用回溯计算来源，报告引用固定报告版本；匹配原计划的完成节点可复用完整结果，不把预览当输入。不同输入、参数或语义不复用。
- `POST /artifacts/{id}/regenerations` 从可用完整成果产生新 ID 的不可变副本，保存来源关系。已清理内容不能恢复；旧成果保留。
- 报告类型支持自动、快速、详细、管理层、技术、质量、预测。ReportDocument 来自已保存计算和事实路径；缺失事实来源拒绝报告生成。编辑标题、顺序和文案保存新版本，并标记用户编辑，计算表格与来源继续保留。
- Excel 包含 Summary、Raw Data、Cleaned Data、Data Quality、KPI、Analysis、Charts、Insights，兼容旧 Metrics。Raw Data 从固定输入追溯原始版本，保存数据集/版本/输入别名；Join 两侧来源纳入报告快照。采用处理版本时另列 Cleaned Data。超出单文件行数限制时分文件并附 JSON 清单，继续防止公式注入。
- Word/PDF 共用结构化 document，提供封面、目录、页眉页脚、页码、表格重复表头和证据附录。DOCX 目录是 Word 字段，打开后可更新页码。图表从保存的 ChartSpec 渲染；预测保留上下界，贡献不推断因果，无适用图表时明确说明。
- Python 导出已完成计划、固定输入类型/版本/语义及依赖说明；必须提供每个输入 CSV，并在同版本 backend 环境本地运行。Decimal 输入保留精度。需要受限写入、旧 Adapter 或 SQL 的步骤会明确停止。SQL 仅导出再次校验的单表 SELECT；没有已验证 SELECT 时说明不支持。没有增加服务器任意代码执行接口。
- Composer 选择报告类型后，分析结束在原监督任务内生成报告和默认 XLSX/DOCX/PDF/Python，接口也支持显式 `output_formats`。分析与交付全部完成才成功；格式失败保留部分成果。手动报告仍使用原队列，创建/导出支持稳定 `request_id` 重放和冲突检查。

## 迁移与运行边界

`0012_artifact_workspace` 增加 Artifact Session/留存分类/可空期限和报告多输入快照，回填旧记录，不生成丢失文件。已有永久成果时禁止自动降库，应使用迁移前备份恢复。代码运行前需在目标数据库正常备份并执行 Alembic upgrade head。

本轮仅在临时 SQLite 和随机命名的隔离 MySQL 测试库验证迁移；完成后删除本轮创建的 MySQL 库。没有迁移本地业务库，没有刷新现有业务服务，没有改用户 `backend/app/config.py` 或 `plan/`。未连接新外部数据源。
