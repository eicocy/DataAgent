# DataAgent V2.0.5

完成 `docs/UPGRADE_PLAN.md` Phase 5：默认关闭的独立 Python 沙箱、任务与输出加固、备份恢复和部署准备。基于 V2.0.4；数据库迁移头保持 `0012_artifact_workspace`，普通注册工具不依赖沙箱。

## 主要变化

- 只有注册工具无法满足且 broker 健康时才生成受限代码提案；模型仅看到字段和固定版本元信息，原始行只进入授权的执行容器。没有任意代码公开 API，不回退宿主执行。
- 固定 Docker 执行边界：非 root、只读、无网络、禁止提权，1 CPU / 512 MiB / 无额外 swap / 64 PID / 60 秒 / 64 MiB 输出；应用和执行容器不持有 Docker socket、模型 Key 或数据库连接。
- AST、固定协议、输出路径/结构及 PNG 重编码校验；结果接入现有证据、Artifact 与报告。取消、租约、OOM、超时及重启孤儿清理明确失败；结果读取后释放内存，驻留输出总量有界。
- 安全日志与 Nginx SSE 加固，可选 Compose 沙箱配置；新增带 SHA-256 manifest 的离线备份、验证和空目录恢复工具及运行手册。
- 修复表格行参与报告事实绑定、overview 预览保留数据集行数、默认关闭时 FAST 预算，以及 Docker tmpfs 输出收集与退出状态竞争。

## 验证与限制

实施中采用针对性检查和固定模型样例；一次独立审查的四项 Important 已复现并修复。发行以最终提交的强制 backend/frontend/sandbox CI 成功为准，包含真实 Linux Docker 隔离与生命周期验证。

最终小模拟数据使用真实 `deepseek-flash` 工作流，3 次模型调用 / 9,218 Token。分析结果、Artifact、报告工作区、认证预览和下载通过；修复报告交付时复用了保存结果，没有追加模型分析。PDF、DOCX、XLSX 各生成并打开检查一个真实文件，PDF/Word 各四页实际查看，Excel 原始两行与来源正确。SSE 回放与重连、隔离 MySQL 0009→0012 及真实 SQL/文件备份恢复通过。

本机 Windows Docker 引擎未就绪，容器验收使用 Linux CI。沙箱 Agent 全链路使用固定 Provider，真实容器另测，未追加付费模型与真实 broker 的组合验证。未执行生产部署、业务库迁移、压力或大规模兼容性测试，不宣称安全认证或跨重启续算。旧缓存预览不自动重写；备份 checksum 不提供加密或来源认证。

详细证据与限制见 [Phase 5 工作区](../phase5-workspace.md)，部署准备与恢复步骤见 [运行手册](../operations.md)。
