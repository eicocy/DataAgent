# 数据生命周期设计

## 创建

上传先建立 datasets 记录并标记 uploading；文件安全落盘后进入 parsing；字段分析成功后写入 dataset_columns 并改为 ready。失败记录错误码，临时文件按状态清理。

## 分析

收到问题先写用户消息和 pending record；执行中更新 running；完成时写 ToolCalls、裁剪结果、ChartSpec、助手消息和耗时。更新必须保证不会出现“记录成功但没有 Tool 结果”的不一致。

## 删除

首期用户确认删除数据集后，在事务中删除/级联其 columns、sessions、messages 和 records；事务成功后删除物理文件。物理文件删除失败进入后台清理记录并告警，不能回滚已确认的数据库删除来制造幽灵资源。

删除单个会话只影响该会话、消息和记录，不影响数据集。用户删除按产品策略处理；首期不提供管理端自助删除。

## 保留

不在 analysis_records 复制完整 DataFrame。Tool Result 保存有限预览和统计摘要。日志与上传临时文件应有独立、可配置的保留期，后续在隐私策略明确后固化。
