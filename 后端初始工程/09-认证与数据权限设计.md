# 认证与数据权限设计

## 认证

首期用户名+密码。密码使用成熟哈希算法（Argon2id 或 bcrypt）并配置成本；登录错误使用泛化文案。认证载体可采用短期 JWT + HttpOnly Cookie 或服务端 Session，正式实现前固定一种，不混用。

## 所有权

Dataset、AnalysisSession、AnalysisMessage、AnalysisRecord 的读取和变更都从当前 user_id 出发。不能先按 id 查出对象再只依赖前端隐藏；Repository 查询应直接包含 owner 条件或通过受控关联校验。

## 权限结果

- 未登录：401。
- 已登录但无权访问：403（若安全策略需要隐藏资源存在性，可统一 404，但必须形成明确决策）。
- 资源确实不存在：404。

## 敏感信息

DeepSeek 密钥只在服务端配置；密码、Token、原始数据内容不进入日志；下载/预览接口同样执行所有权校验。
