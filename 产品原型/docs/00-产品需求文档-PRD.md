# 产品需求文档（PRD）

## 1. 产品背景

普通用户常面临四类阻碍：不会 Python、不会 SQL、Excel 高阶操作复杂、从数据到结论需要反复清洗与切换工具。DataLens Agent 让用户直接用自然语言描述目标，由 Agent 把问题转为结构化 Tool 调用，再用程序完成真实计算并解释结果。

## 2. 产品目标

- 上传 CSV/XLSX 后，在一个工作台完成查询、筛选、聚合、趋势、指标和图表。
- 让用户看到 Agent 做了什么、Tool 使用什么参数、结果来自哪里。
- 保存会话和分析记录，支持回看与再次分析。
- 首期形成可演示的完整闭环，而不是追求复杂算法覆盖。

## 3. 非目标

首期不做多组织协作、复杂权限矩阵、自动机器学习、任意 Python 执行、写入型 SQL、实时数据仓库、移动端原生应用和商业计费。

## 4. 用户角色

| 用户 | 典型目标 | 成功标准 |
|---|---|---|
| 数据分析初学者 | 不写代码得到可信结果 | 能理解字段、步骤和结论 |
| 学生 | 完成课程数据分析 | 过程可解释、可截图展示 |
| 运营人员 | 快速筛选与对比 | 常用问题在几分钟内完成 |
| 销售人员 | 地区/产品业绩分析 | 指标、明细和趋势同屏查看 |
| 小型企业人员 | 低成本分析表格 | 无需专职数据工程团队 |

## 5. 核心场景

1. 上传销售数据，统计各地区销售额。
2. 按月聚合最近 12 个月销售趋势。
3. 筛选销售额超过 5000 元的订单。
4. 将聚合结果生成柱状图，并查看数据表。
5. 用只读 SQL 查询已授权的数据集。
6. 打开历史详情，核对 Tool 参数并再次分析。

## 6. 功能模块

| 模块 | 目标 | 入口 | 输入 | 输出 | 关联 |
|---|---|---|---|---|---|
| 用户系统 | 建立用户身份与数据边界 | 登录/注册 | 账号密码 | 登录态、用户信息 | 全部资源 |
| Dashboard | 汇总使用情况并快速开始 | 登录后首页 | 当前用户 | 指标、最近项目 | 数据集/分析 |
| 数据集管理 | 上传并管理分析对象 | 侧栏数据集 | CSV/XLSX | Dataset/Schema | 工作台 |
| 数据预览 | 验证数据内容 | 数据集详情 | dataset_id | 前 N 行 | 字段信息 |
| 字段信息 | 呈现类型与质量 | 详情字段 Tab | Schema | 类型、缺失、样例 | Agent 上下文 |
| Agent 分析 | 自然语言驱动分析 | 工作台 | dataset_id/question | 执行链路与回答 | Tool/记录 |
| Tool 调用 | 真实、确定性计算 | Agent 内部 | 结构化参数 | ToolResult | 图表/总结 |
| 图表分析 | 可视化聚合结果 | 结果区 | ChartSpec | SVG/ECharts | 数据表 |
| 分析会话 | 组织多轮问题 | 侧栏会话 | dataset/session | 消息列表 | 历史记录 |
| 历史记录 | 审计与复用分析 | 侧栏历史 | 筛选分页 | 记录列表 | 详情 |
| 分析详情 | 回看完整证据 | 历史列表 | record_id | 参数、结果、回答 | 再次分析 |

## 7. 关键指标

- 数据集解析成功率。
- 分析请求成功率与平均耗时。
- Tool 参数校验失败率。
- 从上传成功到首次分析的完成率。
- 历史详情和再次分析的使用率。

## 8. 验收场景

使用统一销售数据集完成“统计不同地区销售额并生成柱状图”，页面同时出现用户问题、`group_by_analysis`、结构化参数、Tool 结果摘要、柱状图、数据表、AI 总结、耗时与成功状态；任一计算步骤失败时不得展示伪成功结论。
